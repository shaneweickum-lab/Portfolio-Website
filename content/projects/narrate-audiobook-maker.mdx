## What it is

A focused tool for authors: drop in a manuscript, have it read back to
you. It's deliberately its own standalone, installable PWA rather than a
page bolted onto this site — a separate app with its own domain, so it can
grow independently of the portfolio around it.

## How it works

Entirely client-side — nothing is uploaded anywhere:

- **Parsing** — `.txt` read directly, `.md` parsed with `marked`'s lexer
  (code blocks skipped), `.docx` parsed with `mammoth.js`. All in the
  browser.
- **Narration** — the [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API)
  reads each paragraph aloud using whatever voices are already installed on
  your device, with play/pause/skip controls and a voice picker.
- Because there's no server in the loop at all, it's fully usable offline
  once installed as a PWA.

## The pivot from a Python backend

This started as a FastAPI + Piper TTS + python-docx backend that rendered
a downloadable MP3 — real, working code, still in git history. Getting it
actually deployed (a persistent host, volumes, Docker) turned into its own
project before the product itself could be tried. Device-native TTS trades
away MP3 export (browsers don't expose synthesized speech as a capturable
file) for zero backend, zero deploy, and zero cost — the right trade for
proving out the core experience first.

## Formats

**.txt**, **.md**, and **.docx** today. PDF is a straightforward addition
later. `.pages` and Google Docs are intentionally out of scope — both
convert cleanly to formats already supported.

## What's next

PDF support, and possibly reviving the Piper-based backend later as an
opt-in "export to MP3" feature once the in-browser experience is proven.
